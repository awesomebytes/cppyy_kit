# Writing rules

- Use plain technical English and short sentences.
- Do not use em dashes or conversational judgments, hype, or LLM-style mannerisms.
- State concrete operations, results, units, and conditions. Link claims to their source.
- Explain why a feature matters to someone using or developing the project.
- Keep technical examples and code used as `@cpp` docstrings intact. Change comments only to clarify factual behavior.
